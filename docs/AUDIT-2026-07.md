# Soundtracks — Full Audit (July 2026)

Post-revival audit across code quality, correctness/robustness, and infra/ops.
Findings verified against the live production project `izfhbtipzuvinyacttin` and the current `main` (post-PR #3).

Status legend: 🔴 fix now · 🟠 fix soon · 🟡 worth doing · ⚪️ optional/leave

---

## 🔴 P0 — Security & data integrity

### 1. `accept-friend-invite` accepts forged auth (VERIFIED on deployed v6)
The **deployed** function decodes the JWT with `atob` and trusts it without verifying the signature, then does a service-role insert using that `sub`. Platform `verify_jwt` is also off.

```js
const payload = JSON.parse(atob(b64));
if (!payload.sub || payload.role !== "authenticated") return error(401, "invalid_claims");
visitorId = payload.sub;   // ← unverified, attacker-controlled
```

**Impact**: anyone can `curl` the endpoint with a self-made unsigned JWT plus any public `friend_invite_token` and force an `accepted` friendship with a user whose UUID they know — no consent. That user's `visibility: 'connections'` moments become readable by the attacker.

**Complication**: the repo version is a *different, already-fixed* file that correctly uses `adminClient.auth.getUser(token)` — but it has a hard `SyntaxError` (`token` declared twice: `:32` from the auth header, `:37` from the body). Deploying as-is breaks all friend invites with a boot error. **Fix the shadowing and redeploy together.**

Every other edge function validates correctly (`delete-account`, `notify-friend`, `send-notifications`) — this one is the outlier.

### 2. Wrong song can be silently saved to a moment
`app/create.tsx:104` — effect reads 9 song params but deps are `[params.songId]` only, and `:93` reads `params.songId ?? ""`, so any two selections lacking an id collide on `""`. Second selection is dropped; the user saves a moment with the **wrong song attached**. Same shape at `app/moment/edit/[id].tsx:139` for the edit path.

### 3. Failed profile fetch can dump an existing user into onboarding and overwrite their data
`contexts/AuthContext.tsx:82-86` — on fetch error with no cache (`signOut` clears it at `:315`), `profile` becomes `null` and `profileReady` true → `app/_layout.tsx:134` routes to `/onboarding`. If the user completes it, `completeOnboarding` (`:413-434`) **overwrites** `favorite_artists`, `favorite_songs`, `genre_preferences`, `birth_year`, `country`. Triggered by signing back in on a flaky connection. The 8s `fetchProfile` timeout race (`:225-228`) produces the same bounce.
**Fix**: distinguish "fetched, onboarding incomplete" from "fetch failed" — a `profileError` flag; never route to onboarding on failure.

## 🟠 P1 — User-facing breakage

### 4. Email confirmation runs `exchangeCodeForSession` twice on a single-use code
`app/(auth)/confirm.tsx:19` handles the confirm route, **and** `hooks/useDeepLinkHandler.ts:138` falls through to `handleAuthDeepLink` for the same URL. PKCE codes are single-use, so the two racing calls mean roughly half of new signups see *"Confirmation failed. The link may have expired"* despite being signed in. The blanket fallback also swallows errors and can feed a Spotify `?code=` to Supabase.
**Fix**: allowlist explicit auth paths instead of "everything unmatched is auth"; exclude `/confirm` since the route owns it.

### 5. Preview binaries embed **no** Supabase URL (VERIFIED via `eas env:list`)
The app reads `EXPO_PUBLIC_SUPABASE_URL` (`lib/supabase.ts:5`), but the EAS **preview** environment only defines `EXPO_PUBLIC_SUPABASE_URL_PREVIEW` / `..._ANON_KEY_PREVIEW`. The `preview` build profile in `eas.json` sets only `EXPO_PUBLIC_APP_ENV`. So a freshly installed beta binary has `undefined` for URL and key and cannot reach Supabase at all until an OTA update lands (the OTA workflow maps the names correctly).
Production is fine — its EAS env uses the correctly-named vars.
**Fix**: rename the preview EAS vars to `EXPO_PUBLIC_SUPABASE_URL` / `EXPO_PUBLIC_SUPABASE_ANON_KEY` inside the `preview` environment. Do this **before** building beta build 20.
*Side effect: this also settles the `push_token` question — the variants genuinely use different DBs, so the single-column design is harmless today.*

### 6. Timeline pagination can silently skip 30 moments
`app/(tabs)/index.tsx` — `handleLoadMore:338` increments `pageRef` *before* fetching; the error path `:290-298` returns without restoring it. One failed page on a spotty connection means rows 30–59 are **never shown** until app restart, with no indication. Pull-to-refresh interleaved with `onEndReached` desyncs the same way.
**Fix**: decrement `pageRef` on append-path error; guard `handleLoadMore` with an in-flight ref.

### 7. `momentCache` consumed without checking the id → wrong moment displayed and autoplayed
`app/moment/[id].tsx:92` calls `consumeCachedMoment()` with no comparison to the route `id`. A swallowed navigation leaves a stale value that the **next** entry consumes — notably a push-notification tap (`app/_layout.tsx:245`), which renders another moment's song, photo, and reflection, and can autoplay it.
**Fix (one line)**: `const c = consumeCachedMoment(); return c?.id === id ? c : null;`

## 🟠 P2 — Infra & ops

### 8. `runtimeVersion: appVersion` is the root cause of the crash near-miss
`app.config.ts` — the runtime version only changes when `version` is hand-edited, so native changes don't bump it and EAS serves JS to binaries lacking the native code (exactly the ExpoSecureStore near-miss).
**Fix**: add a fingerprint gate to `promote-to-production.yml` (and `ota-update.yml`) — `@expo/fingerprint@0.15.4` is already in the tree and `expo-updates` ships `fingerprint:generate`; compare against the newest finished build's `fingerprint.fingerprintHash` from `eas build:list --json` and fail unless a `force` input is set. Longer term, `policy: "fingerprint"`.

### 9. Two production migrations don't exist in the repo
Applied in prod but missing from `supabase/migrations/`: `20260526233149_add_moments_user_created_idx` and `20260529163914_fix_anon_rls_policy_moments`. The second alters the `anon` read policy the public web pages depend on — rebuilding from the repo today would make `web/app/m/[share_token]` and `/c/[invite_code]` return empty.
**Fix**: `supabase db pull`, commit both.

### 10. Nothing ever deletes storage objects — 110 orphans, 52 MB (21% of storage)
`lib/storage.ts` has five uploaders and zero delete helpers; only `delete-account` calls `.remove()`. Moment delete, photo removal on edit, and avatar/cover replacement all leak. Failed/retried creates leak too (`lib/saveMoment.ts:47-52` uploads before insert).
**Privacy angle**: deleted moments' photos remain in a public bucket at deterministic URLs.
`delete-account/index.ts:44-50` is also non-recursive and capped at 1000 — it misses `{userId}/collection_covers/*` and heavy users' overflow.
**Fix**: `deleteMomentPhotos(paths)` helper wired into delete/edit; recursive+paginated account deletion; one-off sweep of the existing 110.

### 11. Sentry sourcemaps are never uploaded for OTA bundles
`sentry-expo-upload-sourcemaps` is invoked nowhere and `SENTRY_AUTH_TOKEN` appears in no workflow (it *does* exist as an EAS env var, so binary builds are covered). Every JS error from an OTA-published bundle — your primary delivery mechanism — lands minified.
**Fix**: add the token as a repo secret + an upload step in both OTA workflows.

### 12. Notification cron has no real health signal
Cron `daily-notifications` runs **hourly** (name is misleading; behavior is correct). It uses `net.http_post`, so `cron.job_run_details.status = 'succeeded'` only means the SQL ran — if the function 500s or the key rotates, pushes stop silently forever. No alerting exists on any edge function.
Also: dead push tokens are never reaped (`send-notifications/index.ts:15-25` discards the Expo response, no receipt polling), and priority-5 re-engagement has no cooldown — a dormant user gets "Still there?" *every day forever*.
**Fix**: heartbeat row + a Sentry cron monitor or a watchdog job; handle `DeviceNotRegistered`; add `last_reengagement_at`.

### 13. Service-role key is provisioned where it's no longer needed
`web/` uses only the anon key now (that's what migration `20260529163914` enabled), but `SUPABASE_SERVICE_ROLE_KEY` is still injected in `pr-checks.yml` (a `pull_request`-triggered workflow — the worst place for a full-RLS-bypass key), plus `web/.env.local(.example)` and presumably Vercel.
**Fix**: remove from all four.

### 14. Workflow hygiene
`actions/checkout@v4` + `setup-node@v4` emit Node 20 deprecation warnings (bump to v5). No `concurrency:` group anywhere — two quick pushes race two `eas update` jobs and the older commit can win. No `permissions:` block, no `timeout-minutes`. `promote-to-production.yml` promotes whatever `main` is at dispatch time with no confirmation input or SHA pinning.

## 🟡 P3 — Quality & maintainability

### 15. No image ever has an error state (38 files use `expo-image`, zero use `onError`/`placeholder`)
This is *why* the blank-thumbnail bug survived for months, and nothing structural has changed.
**Fix**: one `<AppImage>` wrapper with a themed placeholder, transition, and an `onError` that reports to Sentry/PostHog; codemod the call sites.

### 16. Generate Supabase types — kills ~56 of 159 `any`s in one pass
159 `any` annotations, concentrated in `lib/albums.ts` (31) and `lib/friends.ts` (25), almost all the same `(row: any) =>` pattern on untyped Supabase responses. `mcp__supabase__generate_typescript_types` produces a `Database` type that makes `supabase.from()` infer rows. Higher leverage than any file-by-file grind.

### 17. `MOMENT_CARD_COLUMNS` + `mapRowToMoment` trapdoor
The column set omits `user_id`, `people`, `visibility`, `share_token`; `mapRowToMoment` then *defaults* them (`visibility: 'private'`, `userId: undefined`, `people: []`). So every card-derived moment claims to be private with no owner while typed as a full `Moment` — any ownership/visibility check on one silently does the wrong thing (e.g. `app/moment/[id].tsx:323,332`). Nothing is broken today; it's a latent privacy bug.
**Fix**: separate `MomentCard` type, or make partial-row defaults `undefined` rather than safe-looking lies. Also fix the lone hand-mapping at `app/(tabs)/index.tsx:117-133`.

### 18. Patch/version landmine — check before any Expo bump
`patches/expo-web-browser+15.0.10.patch` and `patches/expo-apple-authentication+8.0.8.patch` are version-pinned by filename and carry the iOS 26 `keyWindow` fixes (commits `55345d6`, `6a7ca78`). `expo install --check` wants `expo-web-browser@15.0.11` — bumping silently drops the patch and **reintroduces the shipped ASWebAuthenticationSession crash**. Verify upstream first; rename patches as you bump.
(`patches/expo-share-intent+5.1.1.patch` fixes dropped photos on multi-image share — keep.)

### 19. Dead code — ~500 lines, verified zero-reference
Whole files: `components/TaggedRow.tsx`, `lib/onboardingEvents.ts`, `lib/songSelection.ts`, `app/(tabs)/soon.tsx`. Functions: ~7 abandoned tagged-inbox functions in `lib/friends.ts`, `uploadMomentPhoto` (superseded), `fetchCalendarMonth`, `getRecentlyPlayed`, 3 in `lib/albums.ts`, `consumePendingAlbumId`.
Also unreachable-but-live: `app/shared-albums.tsx` and `app/tagged-moments.tsx` are registered as routes but nothing navigates to them — wire up or delete.
Housekeeping: drop `expo-auth-session` (zero imports); move `why-did-you-render` to devDependencies; make `AGENTS.md` a pointer to `CLAUDE.md` (currently a byte-identical copy); drop the redundant committed `ios/ShareExtension/ShareViewController.swift` (the patch is source of truth).

### 20. `lib/musickit.ts` defeats the AppleMusicProvider lazy-load guard
`AppleMusicProvider.ts:14-19` carefully wraps the native SDK in `getAMSdk()` with a try/catch — but the same file statically imports `@/lib/musickit`, which eagerly imports the native module at top level. Since `AuthContext` imports `getProvider` at startup, Apple Music native loads at boot anyway. Given the crash history, cheap insurance to fix.

### 21. Guest contributions: uncompressed photos, wrong content types, no abuse ceiling
`submit-guest-contribution` never compresses (client-side `compressImage` only runs in-app) — a 40-photo event album is hundreds of MB per scroll and an OOM risk. `photo.type` is passed through verbatim with a `.jpg` name, so HEIC uploads render **broken on Chrome/Firefox/Android** (fine in Safari and the app) and break OG previews; an unvalidated `text/html` would serve as HTML from your storage origin. `verify_jwt: false` + `CORS: *` + no rate limit means anyone with a public invite code can loop 20 MB uploads.

### 22. PostHog mixes beta and prod events
`lib/posthog.ts` sets no environment property and both channels share one API key. One-line fix: register a super-property from `EXPO_PUBLIC_APP_ENV` (already plumbed everywhere).

### 23. Docs assert things that are now false
`docs/DEPLOY.md`: references a nonexistent `app.json`, says manual `buildNumber` edits matter (they don't — `appVersionSource: remote`), claims the `preview` profile uploads to TestFlight (it's `internal`), stale privacy-policy domain, `soundtracks://` regression steps now prod-only.
`docs/PRODUCTION-READINESS.md`: §19 "Zero Test Coverage — no Jest config" (false — vitest, 8 suites, runs in CI); §20 says OTA-on-push publishes to **production** (it publishes to preview — the most dangerous stale line in the docs); §22 references a `development` profile that doesn't exist; §57 describes the service-role-key risk as open (it's resolved).
`CLAUDE.md`: scheme is now per-variant; no mention of the custom Spotify module, `EXPO_PUBLIC_APP_ENV`, Sentry/PostHog, or `npm test`.

### 24. Supabase advisors (prod)
Low priority: `pg_trgm` in `public`; leaked-password protection disabled (dashboard toggle, worth enabling); 13 `SECURITY DEFINER` functions callable by `anon`/`authenticated` — mostly intentional for public sharing, but **`handle_new_user()` is a trigger function with no business in the exposed API** (`REVOKE EXECUTE ... FROM anon, authenticated` is free). Performance: one RLS policy on `moments` re-evaluates `auth.<fn>()` per row (wrap in `(select ...)`); 17 unused indexes (expected at this data volume — ignore).

## ⚪️ Explicitly leave alone

- **The 5 `no-require-imports` lint warnings** — every one is a deliberate lazy-require preventing a startup crash. Add disable comments if the noise bothers you; do **not** convert to imports.
- **~20 of the 45 `exhaustive-deps` warnings** — Reanimated shared values are stable by contract, and the `[obj?.id]` narrowing is intentional. Mechanically "fixing" these will cause re-render loops. This is the single easiest way to make the codebase worse.
- **`react-native-maps@1.27.2`** — you're *ahead* of the SDK expectation (1.20.1), not behind. `expo install --fix` would **downgrade** a native module seven minors.
- **The four inline column lists** (`app/moments-map.tsx:46`, `profile.tsx:99`, `index.tsx:113`, `lib/browse.ts:45`) — deliberately narrower projections; using the shared constant would fetch *more*.
- **Console/TODO cleanup** — nothing to clean (zero `console.log`, zero TODO/FIXME; the six `console.warn` are `__DEV__`-guarded).
- **`Collection*` internal naming drift** — DB columns are still `collection_*`; half-renaming reduces clarity.
- **AASA missing the beta bundle ID** — universal links intentionally resolve to prod.
